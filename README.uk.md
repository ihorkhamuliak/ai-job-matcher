# ai-job-matcher

[English](README.md) | **Українська**

Особистий асистент пошуку роботи, яким я користуюсь щодня, поки шукаю роль в автоматизації та AI у Польщі.
Він читає нові вакансії, відсіює їх звичайним кодом, дає LLM оцінити решту за банком мого реального досвіду
і надсилає короткий дайджест у Telegram. Один тап на вакансії збирає під неї CV на одну сторінку і супровідний лист,
лише з фактів банку.

Це репозиторій **ядра приватної версії**. Адаптерів бордів вакансій тут нема (див.
[Чого тут нема](#чого-тут-нема)); замість них демо-джерело з вигаданими вакансіями, тож кожен крок після джерела
це той самий код, що працює в проді.

## Як це працює

```
джерело (10 бордів у приватній версії, тут examples/jobs.json)
  -> дедуп: одна вакансія з різних міст і бордів = один ключ
  -> сито кодом: вікно, промислова «автоматика», чорний список назв, поріг грошей
  -> позначки правилами: стаж, рівень англійської й польської, третя мова, офіс в іншому місті
  -> черга: спершу досяжні (віддалено, своє місто, Варшава-гібрид), денна стеля, найсвіжіші першими
  -> оцінка LLM 1-10 за банком фактів, мінус 1 за кожну м'яку позначку
  -> дайджест у Telegram: окреме повідомлення на вакансію, кнопки «не те» / «подаюсь»
  -> «подаюсь»: CV (PDF, 1 сторінка) + нотатка для LinkedIn + лист + питання про прогалини, рядок у Google Sheets
```

## Інженерні рішення (заміряні, а не вгадані)

- **Правила в коді, судження в моделі.** Усе детерміноване (стаж, мови, гроші, місто) вирішує код до того, як модель
  побачить вакансію. Модель оцінює лише, наскільки задачі збігаються з моїм досвідом. Правила лежать у
  `jobbot/reqs.py`, `jobbot/money.py` і `jobbot/rank.py`, кожне з випадком, через який з'явилось.
- **Модель обрано тестом.** `scripts/model_bakeoff.py` переоцінює вакансії, які вже оцінила попередня модель.
  Claude Haiku 5.5 вийшла приблизно в 12 разів дешевшою за Sonnet 5.5 ($0.00053 проти $0.0064 за вакансію) і
  суворішою приблизно на 0,6 бала. З порогом дайджесту 5 вона залишила всі вакансії, на які я реально подався
  (11 з 11), і не загубила жодної 8+. CV і листи лишились на Sonnet: там якість важливіша за центи.
- **Модель лише обирає.** Для CV вона обирає варіант summary, п'ять навичок першого рядка і порядок фактів з банку.
  Код рендерить тільки те, що є в банку; навичка, якої вакансія хоче, а банку бракує, стає питанням у Telegram,
  і відповідь повертається в банк.
- **Перевіряємо вихід, а не вхід.** PDF перевіряється витягнутим текстом (одна сторінка, є ім'я, клауза RODO для
  польських CV), а не поглядом на HTML.
- **Датчики замість надії.** Кожен скан шле заголовок, навіть коли нового нема (тиша = бот лежить). У заголовку
  видно джерела, що дали менше 30% від медіани за 7 днів (зламана пагінація), вакансії, що чекають під денною
  стелею, і оцінені картки без реакції понад 2 дні.
- **Тести несуть причину.** 151 тест, багато названо за реальною вакансією чи збоєм, з якого з'явилось правило.

## Запустити демо

```bash
pip install -r requirements.txt
python -m jobbot.scan --no-mark      # без ключа: дедуп, сито і позначки; оцінка пропускається
cp .env.example .env                  # додай ANTHROPIC_API_KEY, щоб оцінити демо-вакансії (частки цента)
python -m pytest -q
```

Для частини з CV потрібен свій `facts.yaml` (форма в `tests/bank_fixture.yaml`), а шаблони листа і перевірка
імені в `jobbot/cv.py` використовують ім'я-заглушку «Jan Kowalski».

Тексти інтерфейсу в Telegram і промпти моделі українською, це моя робоча мова. Коментарі в коді англійською.

## Чого тут нема

- **Адаптерів бордів вакансій.** Більшість польських бордів забороняють автоматичне збирання даних у своїх
  регламентах, тому код, що їх читає, лишається приватним і працює лише для мого власного пошуку.
- **Пошуку контактів і читання пошти.** Вони обробляють персональні дані третіх осіб.
- **Мого банку фактів і CV.** Персональні дані.
